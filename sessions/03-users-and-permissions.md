# الجلسة 3: المستخدمون والمجموعات والصلاحيات

**المدة:** ساعتان · **المكان:** صندوق المختبر · **المتطلبات:** الجلستان 1 و2

## الهدف
أن يفهم الصديق من يستطيع فعل ماذا في النظام، ويعدّل الصلاحيات بوعي. هذا أساس الأمان في أي بيئة DevOps.

## الفكرة في دقيقتين
كل ملف له **مالك** و**مجموعة**، وثلاث فئات تُحدَّد صلاحياتها: المالك (u) والمجموعة (g) والباقون (o).
كل فئة لها `r` قراءة = 4، و`w` كتابة = 2، و`x` تنفيذ = 1.
```
-rwxr-x---   ← المالك: rwx (7)، المجموعة: r-x (5)، الباقون: --- (0)  =  750
```

## ورقة الغش

| الأمر | ماذا يفعل |
|---|---|
| `ls -l` | اعرض المالك والمجموعة والصلاحيات |
| `id` / `whoami` / `groups` | من أنا؟ وفي أي مجموعات؟ |
| `chmod 750 ملف` / `chmod u+x ملف` | غيّر الصلاحيات (رقميًا / رمزيًا) |
| `chown مستخدم:مجموعة ملف` | غيّر المالك والمجموعة |
| `sudo أمر` | نفّذ الأمر بصلاحيات المدير (root) |
| `sudo useradd -m اسم` | أنشئ مستخدمًا (مع مجلد بيت) |
| `sudo groupadd اسم` | أنشئ مجموعة |
| `sudo usermod -aG مجموعة مستخدم` | أضف مستخدمًا إلى مجموعة (**-a** مهمة!) |
| `su - مستخدم` | انتقل إلى مستخدم آخر |

## شغّل ثم افهم
1. `ls -l /etc/passwd /etc/shadow`. لماذا يقرأ الجميع الأول ولا يقرأ الثاني إلا المدير؟
2. جرّب:
   ```bash
   touch ~/test.sh
   ls -l ~/test.sh        # -rw-r--r--
   ./test.sh              # Permission denied: لا صلاحية تنفيذ
   chmod +x ~/test.sh
   ls -l ~/test.sh
   ```
3. أنشئ مستخدمًا: `sudo useradd -m alice` ثم `sudo -u alice cat ~/test.sh`. لماذا فشل؟ (صلاحيات المجلد `~` أيضًا مهمة)
4. تجربة الخطأ الكلاسيكي: `sudo usermod -G devs alice` بدل `-aG` تحذف بقية مجموعات المستخدم! اقرأ `man usermod` عن `-a`.

## التحدي: جهّز مجلد النشر
كل شركة ناشئة لها مجلد تُنشر منه الخدمة. أنشئ الإعداد التالي:
1. مستخدم `deploy` ومجموعة `devs`، و`deploy` عضو في `devs`.
2. مجلد `/srv/startup` ملكه `deploy:devs` وصلاحياته **`2775`**.
3. ملف `/srv/startup/deploy.sh` قابل للتنفيذ (أي سكربت بسيط يطبع `deploying`).

## أسئلة للنقاش
- ماذا يعني الرقم **2** الأول في `2775`؟ (setgid: الملفات الجديدة ترث مجموعة المجلد.) جرّب إنشاء ملف داخل المجلد وانظر مجموعته.
- لماذا لا نعطي كل شيء `chmod 777`؟
- متى تستعمل `sudo` ومتى لا تفعل؟ (مبدأ **أقل صلاحية**)

## ملاحظات للمعلّم
- اشرح النظام الثماني بمثال حسابي مرة واحدة (7 = 4+2+1) ثم دع الصلاحيات تُثبَّت بالتكرار.
- في صندوق المختبر المستخدم `student` يملك `sudo` كاملًا لأن التعلّم يتطلب ذلك. في الأنظمة الحقيقية لا يكون الأمر كذلك.
