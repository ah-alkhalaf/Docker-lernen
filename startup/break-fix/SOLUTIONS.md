# الحلول (للمعلّم، أو بعد المحاولة!)

كل حل يبدأ بـ **العرض**، ثم **التشخيص**، ثم **السبب** و**الإصلاح**.

## 01: اسم المضيف خاطئ
- **التشخيص:** `docker compose --project-directory . -f break-fix/01-wrong-hostname.yaml logs app` يعرض سطرًا مثل `health check failed: could not translate host name "database" to address`.
- **السبب:** `DATABASE_URL` يشير إلى المضيف `database`، لكن الخدمة اسمها `db`. أسماء الخدمات هي أسماء DNS داخل شبكة Compose. فشل الاتصال بقاعدة البيانات ← `/health` يرجع 503 ← `app` لا يصير healthy ← `caddy` لا يبدأ لأنه ينتظر `service_healthy`.
- **الإصلاح:** غيّر `@database:5432` إلى `@db:5432`.

## 02: فحص الصحة على منفذ خاطئ
- **التشخيص:** السجلات سليمة، فالمشكلة في **الفحص نفسه**: `docker inspect --format '{{json .State.Health.Log}}' startup-app-1` يظهر `Connection refused` على المنفذ 5000.
- **السبب:** التطبيق يستمع على **8000** (انظر `CMD` في `app/Dockerfile`) لكن `healthcheck` يفحص `localhost:5000`.
- **الإصلاح:** `http://localhost:8000/health`.
- **الدرس:** فحص صحة خاطئ يقتل خدمة سليمة. الفحص كود أيضًا، ويجب اختباره.

## 03: بوابة سيئة (502)
- **التشخيص:** `docker compose ... logs caddy` يعرض `dial tcp ...: connect: connection refused` مع الوجهة `app:5000`.
- **السبب:** `break-fix/Caddyfile.03` يوجّه إلى `app:5000` والمنفذ الصحيح 8000.
- **الإصلاح:** `reverse_proxy app:8000` ثم `docker compose ... restart caddy`.
- **الدرس:** "كل شيء أخضر" لا يعني أن الأمور صحيحة: الفحوص لا تغطي كل المسارات.

## 04: تصادم المنافذ
- **التشخيص:** الرسالة تذكر المنفذ 8080 صراحة. ابحث عنه: `grep -n 8080 break-fix/04-port-clash.yaml`.
- **السبب:** `caddy` و`uptime-kuma` كلاهما ينشر على منفذ المضيف 8080 (`${HTTP_PORT:-8080}`).
- **الإصلاح:** اجعل Uptime Kuma `"3001:3001"`.
- **الدرس:** منفذ المضيف يُستعمل مرة واحدة فقط، أما منفذ الحاوية فلا مشكلة في تكراره بين حاويات مختلفة.

## 05: فخّ كلمة المرور (يدوي)
- **التشخيص:** `docker compose logs db` يعرض محاولات دخول فاشلة، و`logs app` يعرض `password authentication failed for user "startup"`.
- **السبب:** صورة Postgres تقرأ `POSTGRES_PASSWORD` **مرة واحدة فقط** عند تهيئة مجلد البيانات لأول مرة. بعدها يبقى المخزَّن في الـ volume، وتغيير `.env` لا يغيّره.
- **الإصلاح (بدون خسارة بيانات):** أعد القيمة القديمة في `.env`. أو غيّر كلمة المرور داخل قاعدة البيانات نفسها ثم حدّث `.env` لتطابقها:
  `docker compose exec db psql -U startup -c "ALTER USER startup PASSWORD 'الجديدة';"`
- **الإصلاح (مع خسارة البيانات):** `docker compose down -v` ثم `up -d`. استعمله فقط إذا كانت البيانات بلا قيمة!
- **الدرس:** الإعدادات التي تقرأها الصورة عند التهيئة الأولى فقط، ثم تُخزَّن في الـ volume.
